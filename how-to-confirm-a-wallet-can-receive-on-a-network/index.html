How to Confirm a Wallet Can Receive on a Network

To check if a wallet supports a blockchain before sending funds, open its receive screen on that network, confirm the address, and wait for a test transfer to appear.

By Crypto Docket NewsroomNov 28, 2026 · 04:40 UTC#6355be5 min read

Open the wallet’s receive screen on the destination network and confirm that it shows an address you can use; a small test transfer verifies that funds appear there. This gives you a concrete check before sending the full amount or starting a USDC bridge.

What to have ready

Have your self-custody wallet installed and know the destination network’s name. You also need access to the wallet’s network list or supported-chains page. If you are bridging USDC, identify the receiving chain in the bridge flow before copying an address: the token and destination network need to match the route you intend to use.

Wallet support is specific to the chain, even when two chains use similar addresses. EVM networks such as Base and Arbitrum use addresses beginning with 0x followed by 40 hexadecimal characters. Solana uses base58 addresses and requires a wallet that supports Solana. A familiar-looking address alone does not confirm that the wallet can show or manage funds on the chosen chain.

Verify the destination before sending

  1. Find the destination network. Open the wallet’s network list or supported-chains page and look for the exact network name. The visible result should identify the chain you plan to receive on, such as Base, Arbitrum One, or Solana. Similar names can refer to different networks, so match the destination chain shown by the sender or bridge.
  2. Add a missing EVM network. If the wallet supports custom EVM networks, add the destination and confirm its chain ID against a reliable source for that network. Base uses chain ID 8453; Arbitrum One uses 42161. The visible result should be the selected network in the wallet, with its name and chain ID matching your destination. Adding the network makes its balances visible in the wallet; it does not move funds between chains.
  3. Use a Solana-capable wallet for Solana. Select Solana in a wallet that supports it, such as Phantom, then open the receive screen. The displayed address should be a Solana base58 address, rather than an EVM address starting with 0x. Copy that address directly from the wallet. An EVM address from MetaMask is not a substitute for a Solana receive address.
  4. Open receive on the exact network and copy the address. With the destination network selected, open Receive and copy the address shown for that account. Check that the network label remains visible on the receive screen. An EVM address may look the same across Base and Arbitrum, but the wallet’s selected network determines which chain’s balance it displays. A USDC bridge explanation adds useful route context by showing why the source chain, destination chain, and receiving wallet need to line up.
  5. Send a small test amount. Use the same sending route, asset, and destination network planned for the full transfer. Confirm the destination address before approving the transaction, then wait for it to complete. The visible result is the test amount in the wallet’s balance while the destination network is selected. Once it appears, you have confirmed that the wallet can receive and show funds on that chain.

The EVM case is different from Solana in a practical way. An EVM transfer can reach the same address even when the wallet has not added that network, because the address can be used across EVM chains. The funds remain on the chain where they were sent; adding that chain with the correct ID lets the wallet display its balance. A mailbox analogy helps: the account address is like a unit number repeated across buildings, while each chain is a different building. The analogy ends there, because each blockchain keeps a separate ledger.

That flexibility is useful when the same wallet account is used on Base and Arbitrum, but it can make a transfer look missing if the wallet is still showing another network. Solana requires a separate Solana-capable wallet address, so matching the address format and network matters before sending. For a USDC bridge, check the destination network in the bridge transaction and then verify the receiving wallet on that network; the token name by itself does not identify the chain.

Related

Can I use the same address on Ethereum and Base?

Yes, an EVM wallet can use the same address on Ethereum and Base. The chains keep separate balances, so select Base to see funds sent there. Confirm the destination network before sending, even when the address matches the one you use on Ethereum.

What happens if I send crypto to the wrong network?

The transfer lands on the network selected by the sender, which may leave the funds invisible in the wallet’s current network view. For an EVM chain, adding the correct network may let the wallet show the balance at the same address. For other network combinations, recovery depends on whether the wallet can access the destination chain and asset. The clearest signal that you are ready to send the remaining amount is the test transfer appearing in the wallet balance on the intended network.
